## Introduction

This project is a part of the Practicum II course in Database Management Systems
(DBMS). The main objective of this project is to design and implement a database
system that can efficiently manage and query data. The project involves creating
an expense report management system that allows employees of certain organisation
to submit their expense reports, which can then be reviewed and approved by their
managers.

The data that this system currently handles is generated synthetically, and it
includes information about employees, their expense reports, and the approval
process. The system is designed to be scalable and efficient, allowing for quick
retrieval of data and easy management of expense reports.

## Architecture

The employee first uploads his transactions csv file to an intake folder which
is the same folder as this project working directory. The csv which are stored 
in this folder are fetched periodically by an R script which polls for csv files
every 5 seconds and checks if these files are processed or not. Then the R 
script invokes another R script which processes the csv file to upload the data
to a local SQLite database.

The employee then can login to a web application to create expense reports from
these transactions and these reports will be stored in a cloud NoSQL database. 
As the web app is not developed yet, this process of simulating expense report
creation is done by another R script which generates random expense reports from
the transactions data and uploads it to the NoSQL database.

There is another MySQL database which serves as a data warehouse for this data. 
This database is populated from both the SQLite database as well as the cloud
Mongo database. The data taken from SQLite database is the project information, 
assignments to employees, clients etc. The data taken from Mongo database is 
expense reports, expense allocations to different projects etc. This data is then
used to generate reports and insights for the management.

## How to run the project

1. Initialize the local SQLite database

Run the script `createSQLiteDB.R` to create the local SQLite database and populate
it with the synthetic data. This script will create the necessary tables and insert
the generated data into the database. This synthetic data includes random employees,
random projects, and clients as well as random assignments to employees to these 
projects. The script ensures that each employee is assigned to at least one project.
This script will also create some random categories and subcategories of expenses,
some currencies and card payment methods. 


2. Generate transaction CSV files

Run the script `syntheticDataGenerator.R` to generate synthetic transaction data 
and save this data to a csv file. This script can take a command line argument which
specifies how many transactions are to be included in the generated csv. If it is not
provided, then 500 transactions will be generated. 

Generating at least 5 to 6 files with each file having more than 60 transactions is
recommended to generate a big enough expense report data so that the data warehouse 
analysis will show some interesting insights. 

3. Start the file monitor agent

Run the script `fileMonitorAgent.R` to start the file monitor agent. This agent 
will poll the intake folder every 5 seconds to check for new csv files. If it finds
any csv file which is not processed, then it will invoke the script `loadToSQLite.R`
with the command line parameter as file name of the csv file. This script will
read the csv file and upload the data to the local SQLite database.

Ideally, this script should only upload to SQLite database. But as we don't have the
web app ready, we are also simulating random expense report generation. Thus, after
the transactions are loaded in SQLite, the script will then invoke another R script
`storeExpenseReport.R` which will generate random expense reports from the transactions
data and upload these reports to the cloud MongoDB database. This expense report 
is generated by taking a random sample of transactions from all the transactions in
csv file and then assigning a random projects to these transactions and then creating
an expense report object which will be inserted as a document in Mongo DB.

Even if this file monitor is shut down and started again, it will remember which
csv files are processed and which are not by maintaining a processed files table
in SQLite database. So, it will not process the same file again.

This file monitor agent does not exit and continues to run until it is manually stopped.
So, it can be started at the beginning and then the csv files can be generated by
running the `syntheticDataGenerator.R` script in another terminal window. Otherwise, 
the files can be created first and then the file monitor agent can be started to process
these files. Use CTRL-C to stop this file monitor once it has processed all the files. 

4. Data warehouse population

Run the script `loadToMySql.R` to populate the data warehouse MySQL database. This
script will take the dimension table data like currency, projects, employees, clients,
cards etc to populate the dimension tables in MySQL database. It will take the expense
report data from the cloud Mongo database and populate the fact tables in MySQL database. 
The fact table created will then be highly indexed to allow for efficient querying and
generation of reports and insights.

5. Generate the analysis report

The R notebook `DatamartReport.Rmd` can be run to generate the analysis report. This
notebook will connect to the MySQL database and run some queries to generate insights
and reports for the management. Knit this notebook to generate the final report in HTML
format. 

## File Structure

- `constants.R`: Contains constants and utility functions for the project. This file is sourced by all the files.
- `dbconstants.R`: Contains constants and utility functions for connecting and handling SQLite database.
- `createSQLiteDB.R`: Script to create and populate the local SQLite database with synthetic data.
- `syntheticDataGeneratorConfiguration.R`: Contains constants and utility functions for generating synthetic transaction data.
- `syntheticDataGenerator.R`: Script to generate synthetic transaction data and save it to a csv file.
- `fileMonitorAgent.R`: Script to start the file monitor agent that polls for new csv files and processes them.
- `loadToSQLite.R`: Script to read the csv file and upload the data to the local SQLite database. 
- `storeExpenseReport.R`: Script to generate random expense reports from the transactions data and upload these reports to the cloud MongoDB database.
- `loadToMysqlConfiguration.R`: Contains constants and utility functions for connecting and handling MySQL database.
- `loadToMySql.R`: Script to populate the data warehouse MySQL database with data from SQLite and Mongo database.
- `mongodbconstants.R`: Contains constants and utility functions for connecting and handling MongoDB database.
- `loadFromMongoDB.r`: Script internally called by loadToMySql.R to load data from MongoDB database and insert it to MySQL database.
- `DatamartReport.Rmd`: R notebook to generate analysis report by querying the MySQL database.
